# Change Proof — Visual Grammar V1

## Core character

Precise.
Quiet.
Engineered.
Editorial.
Forensic.
Premium without decoration.

The interface must feel manually designed, not AI-generated.

## Primary rule

One dominant idea per frame.

Everything else supports it.

## Composition

Persistent structure:

LEFT — narrative
CENTER — evidence machine
RIGHT — evidence state

Do not force all three zones to be equally loud.

K1 may use only LEFT + CENTER strongly.
RIGHT may remain minimal until evidence begins accumulating.

## Progressive disclosure

Do not show information before the story needs it.

Orientation:
- closed neutral machine
- no selected test
- no result
- no active Shipping
- no large console
- no CTA

Recorded Change:
- reveal BASE / HEAD difference
- identify Shipping

Trace:
- introduce primary action

HEAD:
- reveal implementation and observation

BASE replay:
- reveal comparison

Verdict:
- reveal final proof

## Typography

Typography carries most of the design.

Use:
- large editorial headline
- short supporting copy
- restrained mono only for evidence/data
- generous line-height
- strict alignment

Avoid:
- excessive labels
- tiny technical text everywhere
- decorative uppercase metadata
- random mono text used only to look technical

## Surfaces

Avoid default dashboard cards.

No card unless it performs a clear product function.

Prefer:
- open space
- alignment
- thin rules
- typography
- direct labels in the scene

Do not use:
- excessive rounded rectangles
- glassmorphism
- floating cards everywhere
- decorative containers

## Icons

Icons only when they clarify an action or entity.

Do not use icons as decoration beside obvious text.

## Color

Neutral:
white / graphite / industrial gray

Cobalt:
current / selected / interactive

Green:
confirmed observation

Magenta:
behavioral mismatch

Color must always have semantic meaning.

## Motion

Motion represents:
- reveal
- registration
- transfer
- comparison
- observation
- resolution

Avoid:
- infinite pulses
- scanning decoration
- glow
- generic parallax
- motion with no semantic job

## Navigation

Do not use SaaS-style progress dots.

If chapter progress exists, prefer quiet typography:

CHANGE   HEAD   TEST   REPLAY   VERDICT

No circles, traffic-light dots, progress rail or onboarding-stepper styling.

## K1 Orientation rule

K1 contains only:

1. Product question
2. Short explanation
3. Closed machine

Optional:
one very quiet evidence-status line.

No:
- large Evidence Console
- CTA
- active Shipping
- open machine
- selected test
- result
- revision hashes
- proof status
- decorative icons

## Anti-slop checklist

Reject the frame if it contains:

- futuristic dashboard styling
- unnecessary cards
- fake technical metadata
- random hashes
- decorative icons
- excessive borders
- glowing accents
- glass panels
- generic AI gradients
- unexplained UI controls
- information shown too early
- multiple competing focal points

## Quality target

The frame should feel closer to:

industrial product editorial
+
high-end software instrumentation
+
luxury consumer product restraint

Not:
SaaS dashboard
cyberpunk UI
AI concept art
developer-tool template
